## The plan

**Serves:** learning

**Size:** L (5)

**What:** the first chapters of a structured guide, following the
journey scalar is for: reading untrusted JSON and YAML; finding things
in it, with `At`, `Get` and `Find`; handling what's missing, with
`Or`, `Then` and `When`; and moving into typed structs with `To`. Each
recipe on earthquake data, generated from an example, with the plain
Go beside it.

**Why:** the guide has seven recipes, where scalar's main use, a feed
of unknown shape on its way to typed Go, deserves a path through it
from first read to struct.

**Steps:**

1. Turn the guide's one Recipes section into chapters, each a `##`
   section, in the order of the journey, with the existing recipes
   moved into the chapter each belongs to. The chapters for 2026-0011
   (text, counting, output, speed) are made now, holding the recipes
   they already have, so the contents show the whole guide.
2. Add recipes, each an example with a plain Go twin in
   `example_howto_test.go`, generated by `TestHowTo`:
   - **Reading loose data:** YAML, one document or several
     (`FromYAML`, `FromYAMLAll`), beside the quick start's JSON.
   - **Finding things:** every value at any depth (`Find` with `..`);
     a filter in JSONPath (`[?…]`); and a route built from data
     (`Get` with a route), as when the fields to read come from a
     config.
   - **When something's missing:** the existing "Reading one event";
     defaults and steps that may come up empty (`Or`, `Then`, `When`);
     and reading without changing the data (`GetOK`, `Autovivify`).
   - **Into typed Go:** numbers that arrive as strings (`To`, which
     numifies as Perl would, where the plain Go needs a type of its
     own); a value that doesn't fit, found by the error's path
     (`DecodeError`); and a part that stays loose inside a struct (a
     `*scalar.SV` field, where the plain Go keeps a
     `json.RawMessage`).
3. Each chapter opens with a paragraph on when scalar is the better
   choice for it and when the plain Go is, and links the reference's
   section and the phrasebook's rows where they exist.
4. The guide's contents list the chapters and their recipes.
5. A CHANGELOG line, the record finished, and the guide's PDF read.

**Done when** each chapter's recipes are generated and checked as
2026-0008 sets out, and the guide's contents follow the chapters.

## What happened

- **Outcome:** done as planned. The guide is nine chapters, from the
  quick start to making it faster, with the contents listing each
  chapter and its recipes. Nine new recipes, each with a plain Go twin
  printing the same, take it from eight to seventeen:
  - Reading loose data: YAML, one document or several.
  - Finding things: every value at any depth; filtering with JSONPath;
    a route built from data.
  - When something's missing: defaults, and steps that may come up
    empty; reading without changing the data; with "Reading one event"
    moved here.
  - Into typed Go: numbers that arrive as strings; finding what doesn't
    fit; a part that stays loose.

  The seven older recipes moved into the chapters 2026-0011 fills:
  working with text, counting and grouping, writing it out, and making
  it faster. Each chapter opens with when scalar is the better choice
  and when the plain Go is, and links the reference, and the
  phrasebook where it has the task. All the examples passed the first
  time they ran.
- **The twins found the costs the chapters describe:** a recursive
  search of `map[string]any`, which sorts the keys as the JSON's order is
  lost; a function to follow a route; a type with its own
  `UnmarshalJSON` for numbers that come quoted; and a second
  `json.Unmarshal` to see the value an `UnmarshalTypeError` names but
  doesn't hold. Where the shape is known, as in filtering with
  JSONPath, a struct does the job in a few more lines.
- **Changes from the plan:**
  - The generator shows a type's methods with the type, as
    `UnmarshalJSON` is called by `encoding/json` without the code
    naming it.
  - A method called only through `encoding/json`, such as
    `SV.UnmarshalJSON` in "A part that stays loose", can't appear in a
    Uses line, which lists only what the code calls; the recipe's prose
    links it instead.
  - Reading the PDF found a comment in a twin claiming document order,
    which it doesn't keep, and three lines long enough to wrap; each was
    fixed in its example.
- **What's left:** 2026-0011 adds recipes to the four later chapters.
