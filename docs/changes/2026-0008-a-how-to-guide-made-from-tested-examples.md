**Status:** open

**Origin:** roadmap 2026-0008, from Iain's wish on 2026-11-09 for a much
more comprehensive, structured and tested how-to guide

**Started:** not yet

## Decisions

- [x] **D1.** Should the guide absorb `docs/EXAMPLES.md`, so that it
  can be retired? No, not for now, Iain agreed on 2026-11-09. The two
  answer different questions: the guide "how do I do this task?", the
  examples "what does this one function do?". A guide covering all 302
  examples would stop being a guide, and one covering only the useful
  ones would lose the promise that every function is shown. The
  examples are also Go's own documentation, shown under each function
  on pkg.go.dev, and EXAMPLES.md is their copy for reading offline.
  Whether it's still needed can be asked again once the guide is
  written, as a decision of its own.
- [x] **D2.** Should the guide be generated by docref, shared in
  lock-step with grammar, or by a test of scalar's own? A test of
  scalar's own first, Iain agreed on 2026-11-09, as it makes the
  testing count for more. The work has two parts: splicing an
  example's body and output into Markdown between markers, which is
  general and is what docref already does for EXAMPLES.md; and the
  guide's own checks (every recipe from an example, the plain Go beside
  it, links to the examples and the phrasebook), which are scalar's
  alone. Both are built and proved in scalar first, without lock-step
  changes while the guide's needs are still being learnt. When
  grammar's session takes up D4, the general part moves into docref,
  identical in both, and the guide's checks stay here.
- [x] **D3.** How should the guide relate to `docs/PERL.md`? It stays
  separate, linked both ways, Iain agreed on 2026-11-09. The phrasebook
  is for someone who thinks in Perl; the guide is for a Go programmer
  with messy data, who may never have used Perl, and merging them would
  make Perl a step on the way into scalar. A phrasebook row is one
  idiom, and a recipe joins several steps into a task, so neither
  breaks cleanly into the other. Their tests differ too: rows are run
  in Perl, and recipes against their own output. Where they overlap, in
  the plain Go, each recipe links the rows for the idioms it uses, and
  the link check keeps those links whole. If writing the chapters shows
  that most recipes are rows strung together, the phrasebook could
  become an appendix to the guide; that would be a decision of its own.
- [x] **D4.** Should grammar's how-to guide follow? Yes, Iain said on
  2026-11-09, taken up in grammar's own session. When it is, the
  general part of D2 moves into docref.
